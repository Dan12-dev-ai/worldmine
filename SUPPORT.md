# Support

## How to get help

| Need | Where |
|---|---|
| Setup / run problems | [docs/troubleshooting.md](docs/troubleshooting.md) — real observed failures and fixes |
| Understanding the system | [docs/architecture.md](docs/architecture.md), [docs/faq.md](docs/faq.md) |
| API behaviour | Swagger UI at `/docs` on a running server; [docs/getting-started.md](docs/getting-started.md) |
| Bug reports | GitHub Issues → **Bug report** template |
| Feature ideas | GitHub Issues → **Feature request** template |
| Security issues | [SECURITY.md](SECURITY.md) — **private** reporting only |

## What to include in a request

The more of these you provide, the faster the response:

- Exact command or URL that fails
- Full traceback / log excerpt (redact secrets!)
- OS, Python version (`python3 --version`), Node version (`node --version`)
- Whether you changed any code or configuration

## What to expect

This is an active-development project maintained in best-effort time. There is no SLA, no guaranteed response window, and no paid support channel. Issues are triaged by the maintainer; PRs following [CONTRIBUTING.md](CONTRIBUTING.md) get priority.

## Commercial / operational questions

Deployment topology, licensing, and partnership topics are outside the scope of issue tracking; see the repository owner's profile for contact options.
